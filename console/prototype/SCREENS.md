# Helix Admin screen checklist

The design reference for the console: every place, every state and the copy
each one shows, drawn in `console/prototype`. It covers the admin features the
console has today (accounts and devices, reports, audit, invites, logs,
configuration, sign-in) and touches nothing Helix Remote does not already do.

**Status: direction A. The shell, the tokens and Overview are rebuilt; the
other screens still show the pre-redesign styling until their own batch
(47 states in 11 screens today).**
Open the prototype at `http://127.0.0.1:5318` (run `python serve.py`), or read
`INTERACTIONS.md` for the generated list of every behaviour.

## Places

The console has one place per job, and every place is reachable from the
shell. Invites exists only on servers that register by invite.

| Place | Screens | What it is for |
|---|---|---|
| **Overview** | Dashboard | The node's counts, readiness and integrations |
| **Users & Devices** | Users, Account | Find a person, see their devices, help or stop them |
| **Invites** (invite-mode servers only) | Invites | Create and cancel one-account codes |
| **Ops & Logs** | Reports, Audit, Logs, Configuration | Moderation, the record of admin actions, the live tail, server settings |
| **Access** | Sign in, Locked console | Enter the console; app lock |
| **Reference** | Component kit | Every shared part in one place, used to review the design |

`registration: 'phone'` hides Invites in the shell; `?invites=1` shows it for
review. The sample data server registers by phone, so the dock has three
places by default.

## The shell — direction A, "control room"

Chosen on 2026-10-22 from the three boards in `REVIEW_0.md`. The console is an
instrument: you are meant to look at it for hours, so the frame tells you where
you are and how the node is doing without you asking.

- **Tokens.** `css/tokens.css` is generated by `tools/themes.py`, which reads
  `orbit/prototype/tools/themes.py` and takes the two themes the messenger
  uses, by the same ids: `orbit` and `night`. Console-only tokens are layout
  and type plus six derived colours (`--rail-ink`, `--rail-ink-2`,
  `--rail-ink-3`, `--rail-line`, `--rail-hover`, `--focus`). No screen writes a
  `#` value; the generator fails on any contrast pair (0 failures today).
- **Theme.** Orbit or Orbit Night, switched from the viewer bar or the
  operator menu, remembered on the device — the same rule as the messenger's
  You > Appearance.
- **Instrument rail (window).** 68 px, always the inverse colour, every tab
  labelled, 48 px tall, focus ring from `--focus`. The active place is the one
  light block; the gradient mark is the way home. The open-report count sits on
  Ops. Invites is absent, not disabled, on a phone-sign-up node.
- **Status strip (window).** One line: the place, the node, its state word, its
  id, when the numbers were last read and how long that took, and Refresh. The
  dot always has a word beside it — Ready, Not ready, Unreachable, Signed out —
  and a maintenance badge appears before any of that when the node is in
  maintenance. The strip belongs to the shell, so no page repeats it.
- **Phone.** The rail becomes a bottom dock whose four tabs are all labelled
  (icon-only was one of the audit's findings), each at least 48 px. Above the
  page, a dark line carries the node id, the read time and the state.
- **Panels, not cards.** Flat surface, 1 px line, 9 px radius, no shadow except
  under the floating dock and the overlays. A panel is a group of decisions,
  never a box around a number.
- **Density.** 34 px rows, 30 px buttons in the strip, 54 px strip, 20 px
  gutters, 13.5 px body. Mono is for facts: ids, node names, counts,
  timestamps, log lines.
- **Keyboard.** `/` search, `j`/`k` move, Enter opens, `Esc` closes or backs
  out, `r` reloads, `?` lists the keys. A screen opts in by marking its rows
  `data-nav-row`.

## Design decisions you approved

1. **The strip carries the status, the page does not (2026-10-22).** No page
   repeats "Online · 42 ms" or offers a second Refresh, and no page title
   duplicates the nav label — the audit found all three on the old Overview.
2. **Four facts, one line (2026-10-22).** The signal strip replaces the six
   equal metric tiles. A count is a number, a word about what it means, and
   nothing else; the database readiness is a line in Service health, not a
   tile shouting "Ready".
3. **No time series, no deltas (2026-10-22).** `GET /v1/ops/metrics` counts are
   node-lifetime and reset at a restart, so the Requests panel shows one axis —
   the share by outcome — and says so. Sparklines and day-over-day changes are
   listed as "needs backend" in `REVIEW_0.md`.
4. **Relative time everywhere, exact on hover (2026-10-22).** `<time>` carries
   the real value in `datetime` and `title`; the short form (`4m`, `3d`) is for
   the audit column, the long form for the rest.
5. **The three failures are named (2026-10-22).** `Kit.loadFailed`,
   `Kit.offline` and `Kit.noPermission` look alike on purpose and differ in
   words and button: the node is not answering, the session has ended, the
   list is empty.
6. **Two layouts, one set of screens (2026-10-22).** A phone pushes a page
   (Users → Account) with a back arrow; a window at 960 px or wider keeps the
   list and shows the selected account beside it. Nothing is duplicated for the
   two layouts.
7. **Ops is one destination with four tabs (2026-10-22).** Reports carries the
   open count; the tabs switch without leaving Ops. This is the real admin IA,
   not a new one.
8. **Invites is conditional (2026-10-22).** It appears only when the server
   registers by invite, in the rail on a window and the dock on a phone. It is
   never shown as an empty, disabled place.
9. **Destructive work asks like an operator tool (2026-10-22).** Suspend asks
   for a reason; Ban asks for a reason and the typed word `BAN`; Delete asks
   for `DELETE`. Cancel is always the default. Each outcome says what was
   written to the audit trail.
10. **Codes are shown once (2026-10-22).** Invite and recovery codes appear in
   one dialog with Copy and a plain warning; the list afterwards carries the
   ID, state and dates, never the code.
11. **Read-only facts look read-only (2026-10-22).** Server identity and
   version are plain prop rows with Copy where useful; switches save at once
   and say so; there is no Save button anywhere.
12. **The log stream says what it is (2026-10-22).** It follows the tail while
   live, has Pause, Reload, Copy and a level filter, and states what the
   redacting logger keeps out of it.
13. **No invented operator features (2026-10-22).** No charts, no paging
   controls, no role management, no per-user message reading. The console
   shows and changes only what the admin API supports.
14. **Status is never colour alone (2026-10-22).** Every dot in the shell and on
   Overview has a word beside it: Ready, Not ready, Unreachable, Signed out. A
   signed-out strip uses a grey dot, not red — the node may be well, we simply
   cannot ask it.
15. **A flag line, not a banner (2026-10-22).** When the whole page means
   something different right now — readiness failed, maintenance on — one
   amber line above the board says what it means for the work. It is a line,
   not a card, and it never repeats the strip.

## Shared parts

- **Page head.** Eyebrow, display title, one-line summary, optional actions on
  the right. On a phone the actions wrap under the title.
- **Snackbar.** Floating above the dock on a phone; gone after 3 s (errors 5 s).
  The server name in the bar updates when the server is renamed.
- **Dialogs.** Confirm, destructive, typed word, reason, password change,
  rename, code-once and invite creation. The destructive button is filled red
  and disabled until its typed word is exact.
- **Sheets.** Used for choosing an option on a phone and as a centred dialog
  on a window.
- **Loading.** Skeleton rows shaped like the real content, plus a quiet
  "Loading …" line. Refresh keeps the page's filters while it waits.
- **Empty.** An icon, a title, one useful sentence, and an action when there
  is one. Each list has its own copy.
- **Error.** "could not be loaded", the effect on the people involved, and
  Try again. Nothing is claimed to have changed.
- **Copy.** Copies an ID, address or code and toasts a plain confirmation.
- **Danger zone.** A red-edged card with one row per action, each explaining
  exactly what it changes.

## Overview (8 states)

`overview`, `overview-loading`, `overview-degraded`, `overview-offline`,
`overview-denied`, `overview-maintenance`, `overview-quiet`, `overview-long` (2× text).

- **Signal strip.** Devices online (live sockets), Undelivered (in mailboxes),
  Failed jobs (out of retries, amber when not zero), Crash reports (last 24 h).
  From `websocketsOpen`, `mailboxBacklog`, `deadJobs`, `crashReports`.
- **Requests panel.** The one big number, then a single-axis bar of 2xx / 4xx /
  5xx with the server-error count and the sockets open now, then the same bar
  again for `jobsFinished` ok / retried / dead. Footnote: counts start again
  when the node restarts.
- **Service health.** Database, Object storage, FCM push, SMS gateway, TURN
  relay — Operational/Set up or Failing/Not set up, with the note that a
  set-up line only says the key is present, not that the provider accepts it.
- **Recent admin actions.** The last four audit rows, newest first, short
  relative time (`4m`) with the exact timestamp in the title. Audit trail →
  opens Ops.
- **Waiting for you.** Open reports and failed jobs, each with its action, and
  under a rule the three facts an operator is asked for most: node id and
  version, sign-up mode, federation and maintenance, and when the session ends.
- **States.** Loading paints a skeleton table in each panel. Not ready puts an
  amber line above the board saying the readiness check failed, turns the
  database line red and the strip amber. Maintenance does the same for what
  maintenance means, and the facts line says "Maintenance on". Unreachable
  replaces the page with `Kit.offline` — a flat panel at its own height, naming
  the address and the last read — and the strip says Unreachable. Session ended
  replaces it with `Kit.noPermission`, warns that an action started earlier may
  have landed, and the strip says Signed out with a grey dot: the node may be
  well, we simply cannot ask it. A node with nothing on it reads every count as
  0, replaces the two bars with one line saying nothing has been answered yet,
  says no admin action has been taken, and drops the two "Nothing" words where
  the Review and Purge links would be. Long data (2× text) drops the grid to one
  column and clips nothing.

## Users & Devices (5 states) and Account (3 states)

Default, loading, empty, error, Suspended filter; Account: active, suspended,
no devices.

- **Summary.** "8 accounts · 6 active · 1 suspended." Search hint "Search by
  Helix name or last 4 digits".
- **Toolbar.** Search, then chips All users / Active / Suspended with counts.
  Refresh at the head.
- **Account card.** Avatar with initial, display name, status pill, `~helix
  name` and phone, device count, joined date and open-report flag. Selected
  on a window with an accent tint and a 3 px accent edge.
- **Wide split.** List left with "N accounts · Select a person to see their
  devices."; account pane right; empty pane "Choose someone from the list."
  A phone pushes the account page and gets a back arrow.
- **Account page.**
  - Hero: avatar, name, status, handle, phone, joined, account ID.
  - **User identity & state:** account ID with Copy, phone, Helix name,
    state, last seen, joined, password Set/Not set, open reports with View.
  - **Devices:** active/revoked counts; rows show name, platform, last seen
    and Revoke. Footer: revoking ends access at the next request; messages
    already on the device are not deleted. No devices: "No devices are
    registered. The person can sign in with a new one."
  - **Administrative actions:** Recovery code ("Create a one-time code that
    lets this person back into their account"), Copy user ID.
  - **Danger zone:** Suspend (reason; blocks sign-in, sending and receiving,
    devices keep keys), Resume, Ban (reason + `BAN`; ends every session),
    Delete (`DELETE`; removes account and devices, does not recall messages).
  - Every action names the person and explains the effect; each is written to
    the audit trail.
- **Empty/error.** "No one has signed up yet." / "Accounts could not be
  loaded." with Try again. Nothing is claimed to have changed for anyone.
- **Suspended filter** shows QuickCash and the suspended account page shows
  Resume instead of Suspend.

## Invites (5 states, invite-mode servers only)

Default, new-code dialog, empty, loading, error.

- **Summary.** "2 open · 5 in total. Each code creates one account and
  expires after seven days." Action: Create invite.
- **Cards.** Short invite ID, state pill (Open, Used, Cancelled, Expired),
  issuer, created and expiry, and who redeemed it. Never the code itself.
- **Create.** Creates at once and shows the code once (`HX-7F2K-QP9D`) with
  Copy and "Code is shown only now"; after closing, only its ID remains.
- **Cancel.** Asks first; "The code stops working at once. Anyone who already
  used it keeps their account." Cancelled and expired invites stay listed.
- **Empty.** "No invites yet." with Create invite.
- **Hidden on phone-mode servers.** Helix Global registers by phone, so the
  place is absent; `?invites=1` shows it for review.

## Ops & Logs

Four tab pages share the header tabs; Reports carries the open count. On a
phone the tabs stay a pill row above the content.

### Reports — User Reports & Moderation (5 states)

Default, resolved filter, loading, empty, error.

- **Summary.** "3 open · 1 resolved · 1 dismissed. A decision is recorded in
  the audit trail."
- **Filters.** Open / Resolved / Dismissed / All, each with a count; newest
  first.
- **Report card.** Category (Abuse, Spam, Impersonation, Other), state pill,
  time, the reported account (name and ID, opens its page) and the reporter,
  then the person's note in full. Resolve and Dismiss act in place and toast
  "rep_1042 resolved · audit trail updated".
- **Empty/error.** "No reports right now." / "Reports could not be loaded."
  with the reassurance that nothing changed for the people waiting.

### Audit — Administrative Audit Trail (5 states)

Default, Access filter, loading, empty, error.

- **Summary.** "Every administrative action on this server, newest first.
  Targets are shown by their short ID." Count of entries on the right.
- **Filters.** All events / Access / Moderation / System. Access includes
  admin sign-in, sign-out and password changes.
- **Row.** Action code, kind pill, target short ID, details (from → to,
  reason, size), exact time. Append-only, no edit affordance.
- **Empty/error.** "Nothing has been recorded yet." / "The audit trail could
  not be loaded." — "No action is lost — this is only the read."

### Logs — Live Server Console (6 states)

Live, paused, warnings filter, loading, empty, error.

- **Summary.** "Structured lines from the server process, newest at the
  bottom. Secrets, keys and full phone numbers never reach this stream."
- **Panel.** Live or Stream paused pill; Reload, Pause/Resume, Copy; filter
  hint "Filter by level, event or text"; count "N of 19 lines"; mono lines
  with time, level, event and message. Errors are tinted red, warnings amber.
- **Behaviour.** Follows the newest line unless paused; Copy copies the
  visible lines and says how many; footer says the console polls every few
  seconds rather than holding a socket.
- **Empty/error.** "The console is quiet." / "The log stream could not be
  reached." — lines are still being written.

### Configuration (4 states)

Default, maintenance on, loading, error.

- **Summary.** "This server's identity, safeguards and feature flags. Changes
  save at once and are written to the audit trail."
- **Server node identity.** Hexagon mark, server name, address and node ID,
  version pill, Rename.
- **Configuration properties.** Public address (Copy), Node ID (Copy),
  Version, Sign-up mode, Attachment limit, Admin session ends.
- **Worldwide mode & peer network.** Switch; off means people can only reach
  accounts on this server; on shows the peer domain. Footer says existing
  chats stay readable.
- **Local security & app lock.** App lock (device setting; screen lock opens
  the console), Change the admin password (signs out other sessions).
- **Node maintenance & clean-up.** Maintenance mode with confirmation and a
  banner while on ("Turn off"); Purge dead jobs and expired rows with counts.
- **Feature flags.** Crash report uploads, Minimal analytics, Group calls.
  Each describes the scope; switching applies server-wide at once.
- **Admin session.** Signed in until … and Sign out (asks first).
- **Empty/error.** Config error keeps every setting visible as unchanged.

## Access

### Sign in (4 states)

Address, password, first-run setup, wrong password.

- **Card.** Gradient Orbit mark, display "Helix Admin" or "Sign in", a soft
  gradient page, centred 420 px card, footer `Helix Admin · v2.4.1`.
- **Address.** Field "Server address" (`https://helix.example.com`), helper
  naming Helix Global's address, Continue. Malformed input is refused in
  place: "Use a full address, like https://helix.example.com."
- **Password.** Server chip with ready dot and host, "Sign in", field with an
  eye, "Change server". Notice: only a key derived from the password is sent.
  Wrong password shows the danger banner and the rate-limit sentence.
- **First-run setup.** "Create admin password", two fields, at least 12
  characters, a warning that whoever reaches a new server first does this.
  Mismatch or short passwords are refused before submitting.
- **Behaviour.** Continue checks the address, then signs in; the password
  never leaves the device. Signing in goes to the dashboard.

### Locked console (1 state)

- "Helix Admin is locked", "Use this device's screen lock to open the
  console.", a lock mark, Unlock. Footer names the server and host.
- App lock is a device setting and never changes the admin password or ends
  the server session.

## Component kit (1 state)

One page showing every shared part: buttons and icon buttons, fields with
errors and password eyes, search, chips, pills, cards, prop rows, setting
rows, switch rows, device rows, metric tiles, health rows, invites, reports,
audit rows, banners, empty/loading/error blocks, dialog and sheet styles.
Used to review the Orbit treatment in isolation.

## Review notes

- The phone dock shows short labels for inactive tabs and the full label on
  the active pill, so "Users & Devices" never crowds the dock; the header on
  a window has room for the full name.
- The server chip is deliberately quiet on a phone (dot plus name); it is not
  a second navigation control.
- Invites is absent by default because the sample server registers by phone.
  Add `?invites=1` to the address to review it.
- All counts and names come from `js/data.js`, fixed to one morning (22 Oct
  2026, ~11:42), so every screen tells the same story.
