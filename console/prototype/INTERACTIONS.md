# Helix Admin interactions

GENERATED by `tools/manifest.py` from the prototype. Do not edit by hand:
change the `interactions` list next to the screen in `js/screens/*.js`, the
app frame's list in `js/app.js`, or the kit's list in `js/kit.js`.

Each item is a behaviour the console must have. Tick it when the review
agrees on it. Gestures: auto, drag, hold, hover, key, long-press, right-click, scroll, swipe, swipe-left, swipe-right, tap, type.

## Every screen (the app frame)

- [ ] **tap** A place in the header (window) or the floating dock (phone): Opens that place. The frame stays where it is; the page changes.
- [ ] **tap** Back arrow on an account page: Returns to Users & Devices.
- [ ] **key** Esc: Closes a dialog first; otherwise goes back one page.
- [ ] **tap** An account row, report card or invite card: Opens it; in a wide window an account opens beside the list instead.
- [ ] **tap** A filter chip or the search field: Narrows the list in place; the count beside each chip is what it would show.
- [ ] **tap** Refresh: Asks the server again and shows the page loading while it waits.
- [ ] **tap** Resolve, Dismiss, Suspend, Resume, Revoke, Cancel, Purge, Create: Runs in place. Anything that changes a person or a session asks first.
- [ ] **tap** Copy beside an ID or a code: Copies it and says so in a toast.
- [ ] **auto** Toasts: Disappear after 3 s; errors stay 5 s and are read out.
- [ ] **auto** The header chip: Shows the server’s name and a ready dot on every signed-in page. Invites appears only on servers that register by invite.
- [ ] **auto** Destructive dialogs: Name the account or job and the effect, and keep Cancel as the default.

## Every page part (the kit)

- [ ] **tap** Switch row: Toggles it; the whole row is the target. Saves at once and says so.
- [ ] **tap** Password eye: Shows or hides the password.
- [ ] **tap** Try again (could not be loaded): Reloads the page; while it waits it shows the skeleton.
- [ ] **type** Typed confirmation (DELETE, BAN): The confirming button stays disabled until the word is exact.
- [ ] **tap** Show a code once: The invite code is shown in a dialog once; after it closes only the code’s ID remains.
- [ ] **auto** Loading lists: Placeholder rows the shape of the real ones, announced as loading.
- [ ] **auto** Destructive dialogs: Keep Cancel as the default and name what will change.

## Overview

### Overview (`overview`, area: overview)

States: `overview`, `overview-loading`, `overview-degraded`, `overview-offline`, `overview-denied`, `overview-maintenance`, `overview-quiet`, `overview-long`

- [ ] **tap** Refresh in the status strip: Asks GET /v1/ops/metrics and GET /v1/admin/config again; the page shows its skeleton while it waits and the strip stamps the new time.
- [ ] **tap** Audit trail →: Opens Ops → Audit at the same list.
- [ ] **tap** Review → / Purge →: Opens the open reports, or the configuration panel where a purge is confirmed.
- [ ] **hover** A relative time: The exact timestamp, from the datetime attribute.
- [ ] **auto** Signal strip: Four counts, each with what it means; failed jobs turn amber when they are not zero.
- [ ] **auto** Maintenance mode: When it is on, the status strip carries the warning before anything else on the page.
- [ ] **auto** A failing readiness check: The database line turns red and the strip stops saying Ready.
- [ ] **auto** A node with nothing on it: Every count reads 0, the bars are replaced by one line saying the node has answered nothing yet, and the audit panel says no action has been taken.
- [ ] **key** r / ?: r checks again, the same as Refresh; ? opens the keyboard sheet. This page has no rows to move through, so it does not advertise j and k.

## Users

### Users & Devices (`users`, area: users)

States: `users`, `users:1`, `users:2`, `users:3`, `users:4`

- [ ] **tap** A person in the list: Opens their account beside the list in a wide window, or as a page on a phone.
- [ ] **type** The search field: Filters by Helix name, display name, phone number or the last four digits.
- [ ] **tap** All users / Active / Suspended: Narrows the list; each chip shows how many it would show.
- [ ] **tap** Refresh: Asks the server again and shows the list’s loading state while it waits.
- [ ] **auto** Account cards: Show state, phone, Helix name, device count, join date and any open reports.
- [ ] **auto** The wide split: Keeps the list while an account is open; the phone pushes the account page with a back arrow.

### Account (`account`, area: users)

States: `account`, `account:1`, `account:2`

- [ ] **tap** Revoke beside a device: Asks first, then ends that device’s access; the other devices keep working.
- [ ] **tap** Create code (recovery): Asks first, then shows a one-time recovery code in a dialog. It is never shown again.
- [ ] **tap** Suspend / Resume: Suspending asks for a reason and blocks sign-in, sending and receiving; resuming lifts it.
- [ ] **tap** Ban: Asks for a reason and the typed word BAN, then ends every session and refuses sign-in.
- [ ] **tap** Delete: Asks for the typed word DELETE, then removes the account and its devices.
- [ ] **tap** Copy account ID or Copy user ID: Copies the ID and says so in a toast.
- [ ] **tap** View beside open reports: Opens User Reports & Moderation.
- [ ] **tap** Back: Returns to Users & Devices.

### Invites (`invites`, area: invites)

States: `invites`, `invites:1`, `invites:2`, `invites:3`, `invites:4`

- [ ] **tap** Create invite: Asks for nothing else, creates the invite and shows its code once in a dialog.
- [ ] **tap** Copy in the code dialog: Copies the code and says so; the code cannot be seen again after the dialog closes.
- [ ] **tap** Cancel beside an open invite: Asks first, then stops the code working and marks the invite cancelled.
- [ ] **auto** Invite cards: Show the short invite ID, state, creation, expiry, issuer and who used it — never the code.
- [ ] **auto** The place itself: Only exists on servers that register by invite; Helix Global registers by phone, so the bar hides it.

## Access

### Sign in (`signin`, area: none)

States: `signin`, `signin:1`, `signin:2`, `signin:error`

- [ ] **type** Server address: The address is remembered for next time; an empty or malformed address is refused in place.
- [ ] **tap** Continue: Checks the address, then shows first-run setup when the server has no admin password, otherwise sign-in.
- [ ] **tap** Change server: Goes back to the address without losing the saved server.
- [ ] **tap** Sign in / Set password and sign in: First-run setup needs two matching passwords of at least 12 characters; then the dashboard opens.
- [ ] **tap** Password eye: Shows or hides the password.
- [ ] **auto** Wrong password: The error banner says the server refused the password and that repeated failures are rate-limited.
- [ ] **auto** The notice under the form: Says the password never leaves the device and only a derived key is sent.

### Locked console (`lock`, area: none)

States: `lock`

- [ ] **tap** Unlock: Asks for this device’s screen lock (biometrics, PIN, pattern or password), then reopens the console.
- [ ] **auto** App lock: Is a device setting; it never changes the admin password or ends the server session.
